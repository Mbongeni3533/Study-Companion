# Deploy Study Companion on Render

Render's free web service is the quickest way to get a public beta URL. It has
an ephemeral filesystem, so this setup uses an **external Postgres database**
instead of SQLite. Uploaded files are only needed while a document is being
processed; extracted text and chunks are stored in Postgres.

## 1. Create a free Postgres database

Use one of these instead of Render's free Postgres, which expires after 30 days:

- **Neon** — create a project and copy the connection string.
- **Supabase** — create a project and copy the connection string from **Connect**.
  Use the pooler connection (port `6543`) if Render cannot reach the direct
  database host.

The connection string should look like:

```text
postgresql://USER:PASSWORD@HOST:5432/DATABASE?sslmode=require
```

The app accepts `postgresql://` or `postgres://` and normalizes it to the
psycopg 3 driver automatically. Supabase strings already include
`?sslmode=require`; the app also disables prepared statements so Supabase's
transaction pooler works safely.

If your password contains special characters, URL-encode it.

## 2. Create the Render Blueprint

1. Push this repository to GitHub.
2. In the Render Dashboard, choose **New → Blueprint**.
3. Connect the `Mbongeni3533/Study-Companion` repository.
4. Render reads `render.yaml` from the repository root.
5. When prompted for `DATABASE_URL`, paste the Postgres connection string.
6. Apply the Blueprint.

The Blueprint creates:

- A free Docker web service named `study-companion`
- `JWT_SECRET` and `BETA_ADMIN_KEY`, generated by Render
- `BETA_INVITE_ONLY=true`
- `ALLOW_ANONYMOUS_SESSIONS=false`
- `DATA_DIR=/tmp/study-companion`
- `OCR_ENABLED=false` to stay within the free plan's 512 MB memory

## 3. Wait for the deploy

The first build installs Tesseract and the Python dependencies, so it takes a few
minutes. When it finishes, open the service URL and check:

```text
https://YOUR-SERVICE.onrender.com/health
```

Expected:

```json
{"status":"ok","app":"Study Companion API","version":"0.2.0","ai_provider":"rules","database":"ok"}
```

## Optional: enable invite emails

Invite links work without email. To send them from the admin page, add these
variables in the Render service's **Environment** tab:

- `RESEND_API_KEY` — your Resend API key
- `RESEND_FROM_EMAIL` — a verified sender, for example
  `Study Companion <invites@yourdomain.com>`

## 4. Create invitation links

1. Open:

   ```text
   https://YOUR-SERVICE.onrender.com/admin
   ```

2. Copy `BETA_ADMIN_KEY` from the Render service's **Environment** tab.
3. Enter it on the admin page.
4. Under **Invitation links**, create and copy a link.
5. Send the link to the beta group.

## Free-tier limits to know

- The service **sleeps after 15 minutes** without traffic. The next request
  takes about a minute to wake it.
- The filesystem is **ephemeral**. Uploaded files disappear on restart or
  redeploy, but the extracted chunks and topics remain in Postgres.
- `OCR_ENABLED=false` means scanned PDFs and image uploads are not OCR'd. Use
  text-based PDFs, or upgrade the plan and enable OCR.
- Free Postgres on Render expires after 30 days, which is why this setup uses
  Neon or Supabase.

For OCR, persistent uploads, or an always-on service, use the
[Oracle Cloud deployment](../oracle-cloud/README.md) instead.
